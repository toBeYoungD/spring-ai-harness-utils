## 二、前后端联动（核心）

### 链路

```
前端 src/services/api.js (axios)
   │  Vite dev proxy: /api/** 、/mcp  ->  http://localhost:8080   （生产直连）
   ▼
后端 :8080
   ├─ /api/v1/workspace/**   Authorization: {system}-{agent}-{user}   ->  WorkspaceApiController
   ├─ /api/v1/admin/**       X-Admin-Token                            ->  Admin controller（跨工作区管理）
   ├─ /api/v1/...attachment  （UUID 路径隔离）                          ->  AttachmentController
   └─ /mcp                   Authorization（JSON-RPC 2.0）             ->  MCP tools（FileSystemTools / SkillTools / RelayTools）
```

### 核心抽象：REST controller 与 MCP tools 共用同一套存储栈

```
请求 -> HeaderAuthenticationProvider -> WorkspaceIdentity({system}-{agent}-{user})
      -> StorageProviderFactory.getStorageProvider(ctx)
      -> AliyunOssStorage（prefix: mcp/workspaces/{system}-{agent}-{user}/）
         + 装饰器：ObservedStorageProvider（可观测，可关）/ QuotaEnforcedStorageProvider（配额，默认开）
      -> FileContentProcessor（唯一内容解析路径）
      -> Aliyun OSS
```

**身份、路径隔离、配额、快照只在一处实现**。加后端能力时 REST 与 MCP 两条路都须考虑。

### 端点表

| api.js 方法 | 后端端点 | 鉴权头 |
|---|---|---|
| `listFiles` / `getFileContent` / `uploadFile` / `deleteFile` / `moveFile` | `/api/v1/workspace/files` 系列 | `Authorization: {system}-{agent}-{user}` |
| `listSnapshots` / `rewind` | `/api/v1/workspace/snapshots`、`/rewind/{id}` | `Authorization` |
| `listWorkspaces` / admin 文件操作 | `/api/v1/admin/workspaces` 系列 | `X-Admin-Token` |
| `callMcp` | `POST /mcp`（JSON-RPC） | `Authorization` |

> 配额管理 / 日志审计控制台目前 **mock 数据**，api.js 尚无对应方法（后端待对接）。

## 三、当前生效约束速览

### 前端
- **antd 全工程锁 4.7**（自 v5 降级）。React18+4.7 有非阻断警告；回退 4.24.x。
- 用 **v4 API**：`Tabs.TabPane` / `Modal/Drawer visible` / `Breadcrumb.Item` / `ConfigProvider` 不带 `theme`。勿用 v5-only（`Flex`/`Segmented`/`Tour` 等）。
- **亮色控制台** `QuotaConsole`/`AuditConsole`：CSS 作用域隔离（`.console-light`/`.console-modal`/`.console-drawer` + `!important`），不污染暗色组件。**主题统一待定**。

### 后端 / 安全
- **workspace 隔离**：身份来自 `Authorization: {system}-{agent}-{user}`。绝对路径（leading `/`）抛 `SecurityException`。
- **配额**：per `{system-agent-user}`，默认 1GB，装饰器实现。领域二计费暂不考虑。
- **file permission**：用户自服务，`{system-agent-user}` 三段身份；管理员跨工作区管理。
- **Phase2 审计**：行为日志 + 管理员操作日志。行为日志由 `@McpTool` 切面记录（**tools/call 拦截**）。
- **MCP gateway** 暂忽略。

### 文档 / 协作
- **中文回答**；技术方案讲抽象（为什么做、做什么），评审用。
- **drawio** 改后必须做坐标几何 + XML 转义校验。
- 中文注释、英文代码。无 `System.out.println`。

## 五、internal-dev 复刻流程

- **分支**：`internal-dev`（单一长期工作分支），不在 `main` 直接改。
- **交付物**：代码 + dev-spec（可同一 commit）。代码是 ground truth，dev-spec 是导航。
- **dev-spec**：散文 + 关键片段，**必含依赖敏感点**（公司内差异 + 适配建议）。NN 递增，不重写历史。
- **commit**：`feat/app-layer(NN): ...` / `docs/spec(NN): ...`，正文引用 dev-spec 路径，末尾 `Co-Authored-By`。
- **push**：默认本地，仅按要求 push。
- **复刻**：按 NN 顺序逐份复刻 → 命中依赖敏感点按说明适配 → 验证 → 提交。
