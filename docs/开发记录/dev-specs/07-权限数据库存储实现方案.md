# dev-spec 07：文件/工具权限改用数据库存储--同步说明（含完整源码）

> **元信息**
> - 任务简述：将权限存储从 yaml 改为数据库（无 identity 表 + admin/user ACL 分两表），给出参考实现与改造建议。
> - 分支：`internal-dev`（本文档为参考实现，外部仓库不落 DB 代码）
> - 依赖敏感点摘要：需引入 `spring-boot-starter-jdbc` + 数据库驱动；表结构由公司内已建，本文档按假设字段名给参考 SQL，字段不同则调整映射。

---

## 一、背景

- 04/05/06 的权限存储是 yaml（`PermissionProperties` 读写 `application.properties`）。
- 改用数据库存储：配置面 REST 写 DB -> 启动加载到内存缓存 -> 运行时零 DB 调用（遵循技术方案 5.4）。
- 表结构按用户决策：**无 identity 表** + **admin/user ACL 分两张表**。

## 二、表结构参考（按假设字段名）

> 字段名/类型按惯例假设。**你公司内已建的表若字段名不同，调整 `DbPermissionStore` 的 SQL 与 `RowMapper` 即可**，接口与判定逻辑不变。

### 表 1：`tool_permission_denied`（工具权限黑名单，按人）

```sql
CREATE TABLE tool_permission_denied (
    id           BIGINT PRIMARY KEY AUTO_INCREMENT,
    identity_key VARCHAR(128) NOT NULL,          -- {system}-{agent}-{user}
    tool_name    VARCHAR(64)  NOT NULL,           -- 被禁工具名；'*' = 全禁
    created_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_identity_tool (identity_key, tool_name),
    INDEX idx_identity (identity_key)
);
```

### 表 2：`admin_acl_rule`（管理员全局文件 ACL 规则）

```sql
CREATE TABLE admin_acl_rule (
    id         BIGINT PRIMARY KEY AUTO_INCREMENT,
    pattern    VARCHAR(256) NOT NULL,             -- glob，如 secrets/**
    access     VARCHAR(8)  NOT NULL,              -- DENY / READ / WRITE
    priority   INT NOT NULL DEFAULT 10,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

### 表 3：`user_acl_rule`（用户自服务文件 ACL 规则，按人）

```sql
CREATE TABLE user_acl_rule (
    id           BIGINT PRIMARY KEY AUTO_INCREMENT,
    identity_key VARCHAR(128) NOT NULL,
    pattern      VARCHAR(256) NOT NULL,
    access       VARCHAR(8)  NOT NULL,
    priority     INT NOT NULL DEFAULT 10,
    created_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_identity (identity_key)
);
```

### 字段说明

- 三张表统一用 `identity_key = {system}-{agent}-{user}`，无 identity 注册表。
- `access` 存枚举字符串（`DENY`/`READ`/`WRITE`），与 `PermissionConfig.Access` 一致。
- `default-policy`（admin/user 的 allow-all/deny-all 兜底）**不进 DB**，保留在 yaml（全局开关，少改）。

## 三、PermissionStore 接口（存储无关）

新增 `permission/PermissionStore.java`：

```java
package io.github.springai.harness.permission;

import java.util.List;
import java.util.Set;

/**
 * 权限存储接口 -- 配置面 CRUD + 运行时加载。
 *
 * <p>两个实现：
 * <ul>
 *   <li>{@link YamlPermissionStore} -- 包装现有 {@link io.github.springai.harness.autoconfig.PermissionProperties}，yaml 存储</li>
 *   <li>{@link DbPermissionStore} -- 数据库存储（本文档实现）</li>
 * </ul>
 * 由配置 {@code spring.ai.harness.mcp.server.permission.storage=yaml|db} 切换。
 */
public interface PermissionStore {

    /** 运行时：加载某身份的完整权限配置（工具黑名单 + admin/user ACL） */
    PermissionConfig loadByIdentity(String identityKey);

    // ===== 工具权限（配置面 CRUD）=====
    Set<String> loadDeniedTools(String identityKey);
    void saveDeniedTools(String identityKey, Set<String> toolNames);  // 替换全部
    void deleteDeniedTools(String identityKey);

    // ===== 管理员全局 ACL（配置面 CRUD）=====
    List<PermissionConfig.AclRule> loadAdminRules();
    void saveAdminRule(PermissionConfig.AclRule rule);
    void deleteAdminRule(Long id);

    // ===== 用户自服务 ACL（配置面 CRUD）=====
    List<PermissionConfig.AclRule> loadUserRules(String identityKey);
    void saveUserRule(String identityKey, PermissionConfig.AclRule rule);
    void deleteUserRule(Long id);
}
```

## 四、DbPermissionStore 完整源码（JdbcTemplate）

新增 `permission/DbPermissionStore.java`。依赖 `spring-boot-starter-jdbc`（公司内 pom 引入）。

```java
package io.github.springai.harness.permission;

import io.github.springai.harness.autoconfig.PermissionProperties;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.jdbc.core.RowMapper;

import java.util.List;
import java.util.Set;
import java.util.stream.Collectors;

/**
 * 数据库存储实现 -- 配置面 CRUD + 运行时加载。
 *
 * <p>表结构见 dev-spec 07「二」。字段名按假设，若公司内表字段不同，调整 SQL 与 RowMapper。
 *
 * <p>default-policy 仍读 yaml（PermissionProperties），DB 只存规则数据。
 */
@Slf4j
@RequiredArgsConstructor
public class DbPermissionStore implements PermissionStore {

    private final JdbcTemplate jdbcTemplate;
    private final PermissionProperties properties;  // 读 default-policy / enabled

    private static final RowMapper<PermissionConfig.AclRule> RULE_MAPPER = (rs, rowNum) ->
            new PermissionConfig.AclRule(
                    rs.getString("pattern"),
                    PermissionConfig.Access.valueOf(rs.getString("access")),
                    rs.getInt("priority"));

    // ===== 运行时加载 =====

    @Override
    public PermissionConfig loadByIdentity(String identityKey) {
        if (!properties.isEnabled()) {
            return PermissionConfig.disabled();
        }

        Set<String> deniedTools = loadDeniedTools(identityKey);
        List<PermissionConfig.AclRule> adminRules = loadAdminRules();
        List<PermissionConfig.AclRule> userRules = loadUserRules(identityKey);

        PermissionConfig.ToolPermissionConfig toolPerm =
                new PermissionConfig.ToolPermissionConfig(deniedTools);

        PermissionConfig.FileAclConfig.Policy adminPolicy = toPolicy(properties.getAdminAclDefaultPolicy());
        PermissionConfig.FileAclConfig.Policy userPolicy = toPolicy(properties.getUserAclDefaultPolicy());

        return PermissionConfig.builder()
                .enabled(true)
                .toolPermission(toolPerm)
                .fileAcl(new PermissionConfig.FileAclConfig(adminPolicy, adminRules, userPolicy, userRules))
                .build();
    }

    private PermissionConfig.FileAclConfig.Policy toPolicy(PermissionProperties.Policy p) {
        return p == PermissionProperties.Policy.DENY_ALL
                ? PermissionConfig.FileAclConfig.Policy.DENY_ALL
                : PermissionConfig.FileAclConfig.Policy.ALLOW_ALL;
    }

    // ===== 工具权限 =====

    @Override
    public Set<String> loadDeniedTools(String identityKey) {
        return jdbcTemplate.queryForList(
                "SELECT tool_name FROM tool_permission_denied WHERE identity_key = ?",
                String.class, identityKey).stream().collect(Collectors.toSet());
    }

    @Override
    public void saveDeniedTools(String identityKey, Set<String> toolNames) {
        // 替换全部：先删后插
        deleteDeniedTools(identityKey);
        for (String tool : toolNames) {
            jdbcTemplate.update(
                    "INSERT INTO tool_permission_denied (identity_key, tool_name) VALUES (?, ?)",
                    identityKey, tool);
        }
    }

    @Override
    public void deleteDeniedTools(String identityKey) {
        jdbcTemplate.update("DELETE FROM tool_permission_denied WHERE identity_key = ?", identityKey);
    }

    // ===== 管理员全局 ACL =====

    @Override
    public List<PermissionConfig.AclRule> loadAdminRules() {
        return jdbcTemplate.query(
                "SELECT pattern, access, priority FROM admin_acl_rule", RULE_MAPPER);
    }

    @Override
    public void saveAdminRule(PermissionConfig.AclRule rule) {
        jdbcTemplate.update(
                "INSERT INTO admin_acl_rule (pattern, access, priority) VALUES (?, ?, ?)",
                rule.pattern(), rule.access().name(), rule.priority());
    }

    @Override
    public void deleteAdminRule(Long id) {
        jdbcTemplate.update("DELETE FROM admin_acl_rule WHERE id = ?", id);
    }

    // ===== 用户自服务 ACL =====

    @Override
    public List<PermissionConfig.AclRule> loadUserRules(String identityKey) {
        return jdbcTemplate.query(
                "SELECT pattern, access, priority FROM user_acl_rule WHERE identity_key = ?",
                RULE_MAPPER, identityKey);
    }

    @Override
    public void saveUserRule(String identityKey, PermissionConfig.AclRule rule) {
        jdbcTemplate.update(
                "INSERT INTO user_acl_rule (identity_key, pattern, access, priority) VALUES (?, ?, ?, ?)",
                identityKey, rule.pattern(), rule.access().name(), rule.priority());
    }

    @Override
    public void deleteUserRule(Long id) {
        jdbcTemplate.update("DELETE FROM user_acl_rule WHERE id = ?", id);
    }
}
```

## 五、YamlPermissionStore 适配（包装现有 PermissionProperties）

新增 `permission/YamlPermissionStore.java`，把现有 yaml 读取逻辑包装成 Store 实现，保持向后兼容：

```java
package io.github.springai.harness.permission;

import io.github.springai.harness.autoconfig.PermissionProperties;
import lombok.RequiredArgsConstructor;

import java.util.List;
import java.util.Set;

/**
 * yaml 存储实现 -- 包装 PermissionProperties，保持向后兼容。
 * 外部仓库默认用此实现；公司内切 DB 时换 DbPermissionStore。
 */
@RequiredArgsConstructor
public class YamlPermissionStore implements PermissionStore {

    private final PermissionProperties properties;

    @Override
    public PermissionConfig loadByIdentity(String identityKey) {
        return properties.toPermissionConfig(identityKey);
    }

    // 配置面 CRUD 在 yaml 模式下不支持写（yaml 只读，由运维改配置文件）
    // 若需要管理台写 yaml，另实现；DB 模式才支持运行时写

    @Override
    public Set<String> loadDeniedTools(String identityKey) {
        return properties.toPermissionConfig(identityKey).toolPermission().deniedTools();
    }

    @Override
    public void saveDeniedTools(String identityKey, Set<String> toolNames) {
        throw new UnsupportedOperationException("yaml 模式不支持运行时写，请改用 db 存储");
    }

    @Override
    public void deleteDeniedTools(String identityKey) {
        throw new UnsupportedOperationException("yaml 模式不支持运行时写");
    }

    @Override
    public List<PermissionConfig.AclRule> loadAdminRules() {
        return properties.getFileAclRules().stream()
                .map(r -> new PermissionConfig.AclRule(r.getPattern(), r.getAccess(), r.getPriority()))
                .toList();
    }

    @Override
    public void saveAdminRule(PermissionConfig.AclRule rule) {
        throw new UnsupportedOperationException("yaml 模式不支持运行时写");
    }

    @Override
    public void deleteAdminRule(Long id) {
        throw new UnsupportedOperationException("yaml 模式不支持运行时写");
    }

    @Override
    public List<PermissionConfig.AclRule> loadUserRules(String identityKey) {
        return properties.getUserFileAcls().getOrDefault(identityKey, List.of()).stream()
                .map(r -> new PermissionConfig.AclRule(r.getPattern(), r.getAccess(), r.getPriority()))
                .toList();
    }

    @Override
    public void saveUserRule(String identityKey, PermissionConfig.AclRule rule) {
        throw new UnsupportedOperationException("yaml 模式不支持运行时写");
    }

    @Override
    public void deleteUserRule(Long id) {
        throw new UnsupportedOperationException("yaml 模式不支持运行时写");
    }
}
```

## 七、AutoConfiguration 注册 + 存储切换

`HarnessMcpServerAutoConfiguration` 按 `permission.storage` 配置注册对应 Store：

```java
@Bean
@ConditionalOnMissingBean
@ConditionalOnProperty(prefix = "spring.ai.harness.mcp.server.permission", name = "storage", havingValue = "db", matchIfMissing = false)
public PermissionStore dbPermissionStore(JdbcTemplate jdbcTemplate, HarnessMcpServerProperties properties) {
    return new DbPermissionStore(jdbcTemplate, properties.getPermission());
}

@Bean
@ConditionalOnMissingBean(PermissionStore.class)
public PermissionStore yamlPermissionStore(HarnessMcpServerProperties properties) {
    return new YamlPermissionStore(properties.getPermission());
}
```

配置：

```properties
spring.ai.harness.mcp.server.permission.storage=db   # yaml（默认）| db
```

DB 模式还需配数据源（Spring Boot 标准）：

```properties
spring.datasource.url=jdbc:mysql://...
spring.datasource.username=...
spring.datasource.password=...
```

## 八、缓存与热下发

运行时热路径**不查 DB**（5.4 原则）。三层：

```
配置面 REST 写 DB
   ↓
PermissionStore 通知缓存刷新
   ↓
本地内存缓存 Map<identityKey, PermissionConfig> 更新
   ↓
PermissionEnforcedStorageProvider 每请求查本地缓存（零 DB 调用）
```

### 缓存实现建议

在 `PermissionStore` 之上包一层 `CachingPermissionStore`（装饰器）：

```java
public class CachingPermissionStore implements PermissionStore {
    private final PermissionStore delegate;
    private final ConcurrentHashMap<String, PermissionConfig> cache = new ConcurrentHashMap<>();

    @Override
    public PermissionConfig loadByIdentity(String identityKey) {
        return cache.computeIfAbsent(identityKey, delegate::loadByIdentity);
    }

    // 写操作后清除对应缓存
    @Override
    public void saveDeniedTools(String identityKey, Set<String> toolNames) {
        delegate.saveDeniedTools(identityKey, toolNames);
        cache.remove(identityKey);
    }
    // ... 其他写操作同样 invalidate
}
```

### 热下发（多节点）

- **单机**：写后直接 `cache.remove(identityKey)` 即可
- **分布式**：DB 加版本号表 / Redis pub-sub / 定时轮询版本号，各节点收到变更通知后 `cache.remove`
- **最简起步**：定时全量清缓存（如每 30s `cache.clear()`），或每请求检查版本号

## 九、改造建议（迁移步骤）

1. **建表**：按「二」DDL（或对照你公司已建的表，调整字段映射）
2. **引入依赖**：pom 加 `spring-boot-starter-jdbc` + 数据库驱动
3. **新增文件**：
   - `permission/PermissionStore.java`（接口）
   - `permission/DbPermissionStore.java`（JdbcTemplate 实现）
   - `permission/YamlPermissionStore.java`（yaml 适配，保持兼容）
   - 可选 `permission/CachingPermissionStore.java`（缓存装饰器）
4. **改造文件**：
   - `DefaultStorageProviderFactory`：注入 `PermissionStore` 替代直接调 `PermissionProperties`
   - `HarnessMcpServerAutoConfiguration`：按 `storage` 配置注册 Store
5. **配置**：`permission.storage=db` + 数据源
6. **配置面 REST Controller**（Phase 3）：注入 `PermissionStore`，CRUD 写 DB
7. **验证**：启动加载 -> `/mcp` 调用走缓存 -> REST 改规则 -> 缓存刷新 -> 新规则生效

### 与 04/05/06 的关系

- **04（yaml 执行面）+ 05（单测）+ 06（按人维度）保持不变**：执行面装饰器、判定引擎、AND 合全不动
- **本次只换存储层**：`PermissionProperties` 从"规则存储"降级为"全局开关 + default-policy"，规则数据移到 DB
- `PermissionConfig` / `FileAclMatcher` / `PermissionEnforcedStorageProvider` 零改动

## 十、依赖敏感点

| 项目 | 说明 |
|---|---|
| 新增依赖 | `spring-boot-starter-jdbc` + 数据库驱动（mysql/postgres 等） |
| 字段映射 | 表字段名若与本文假设不同，调整 `DbPermissionStore` 的 SQL 与 `RowMapper` |
| 向后兼容 | `storage=yaml`（默认）时行为与 04/06 完全一致，无破坏 |
| 缓存 | 必须加 `CachingPermissionStore`，否则每请求查 DB 违反 5.4 热路径原则 |
| 分布式 | 多节点需热下发通道（版本号/pub-sub/轮询），单机可省 |
| `identity_key` 解析 | 无 identity 表，管理台若需展示三段/按 system 聚合，需从字符串解析（注意 user 名含 `-` 的风险） |
| 公司内适配 | 表 DDL、数据源、存储切换配置按公司实际 |

## 十一、无 identity 表的影响（设计取舍回顾）

| 场景 | 影响 |
|---|---|
| 运行时判定 | 无（按 identity_key 查规则） |
| 管理台列已配用户 | 需 `SELECT DISTINCT identity_key FROM (tool_permission_denied UNION user_acl_rule)` |
| 按 system 聚合统计 | 从 identity_key 字符串解析，SQL 不优雅，user 名含 `-` 有风险 |
| 删用户 | 手动删三张表的对应行（无级联） |
| 新建用户配权限 | 直接写规则表，无需先注册身份（简化） |

若管理台需要用户维度视图（stat 卡、按 system 筛选），建议在规则表冗余 `system` 列，或后续补 identity 表。
